# Structured resource package v1

9618 content is prepared and reviewed before import. The MCQ PDF splitter must not process it. No official syllabus, textbook, exam, or answers are bundled with the website migration.

The package is UTF-8 JSON. `shared/structured-content.js` exports the version, validator, stable ID helper, ordered fragment reader, and structured display-block reader used by the site. Validate before uploading with `node tools/validate-resource-package.mjs path/to/package.json`. Validation does not upload or publish anything.

```json
{
  "schemaVersion": 1,
  "subjectCode": "9618",
  "files": [{"storageKey": "resources/9618/example.pdf", "localPath": "files/example.pdf", "contentType": "application/pdf"}],
  "resources": [],
  "papers": [],
  "questions": []
}
```

`files` declares every R2 object referenced by the manifest. Keep `localPath` relative to the package directory. Each record may include `sha256`. Object keys must be relative and must not contain `..`. Upload all declared bytes before publishing database records. Failed or incomplete imports remain draft; replace records by primary key rather than deleting legacy rows. A repeat import updates the same resource ID, paper slug, or question ID. Production publication is a separate step from this website preparation.

## Resources and independent directories

Each resource has `id`, `kind` (`syllabus`, `textbook`, `insert`, `source`, or `other`), `title`, optional `titleZh`, `version`, `examYearStart`, `examYearEnd`, `paperSlug`, `storageKey`, `contentType`, `status` (`draft`, `published`, or `archived`), and `metadata`. Store it in `subject_resources` using the corresponding snake-case columns. QP/MS originals belong in `exam_papers`, not duplicated resource rows.

`metadata.directory` holds an ordered recursive tree of `{id, code, title, titleZh?, children: []}`. Syllabus and textbook directories are independent. Textbook nodes can add `syllabusSectionIds`; `metadata.chapterMappings` can hold `{textbookSectionId, syllabusSectionId}`. Only mapped textbook sections offer chapter question filters. A PDF without an extracted directory remains readable. Versions and exam years always come from the resource manifest.

To use chapter filters in the existing builder, also upsert the mapped nodes into `curriculum_versions`, `curriculum_sections`, `coursebook_chapters`, `coursebook_sections`, `coursebook_section_mappings`, and reviewed `question_section_mappings`. Resource metadata supports browsing even when those optional mappings are absent. Missing mappings must never block source-paper selection.

## Paper metadata and originals

Each paper has `slug` (for example `9618_s26_qp_31`), `paperNumber` 1–4, `year`, `season` (`m`, `s`, `w`), `variant`, `paperType` (`structured` or `practical`), actual `durationMinutes`, actual `totalMarks`, `sourceQuestionCount`, `validQuestionCount`, `qpFileName`, `msFileName`, optional `qpStorageKey`, `msStorageKey`, `status`, and `metadata`. Source-only papers use `validQuestionCount: 0`. Historical metadata overrides the component presets.

The default original file locations are `papers/<slug>/qp.pdf` and `papers/<slug>/ms.pdf`. A release may use `metadata.contentPrefix: "releases/<UUID>"`. Explicit `metadata.qpStorageKey` and `metadata.msStorageKey` take precedence for packages with alternate locations. Original downloads preserve the site's existing access rule. Paper 4 Insert/source files are resources linked by `paperSlug`; Paper 4 never enters the question bank or builder candidate pool.

## Complete parent questions

Each question has `id`, `paperSlug`, original integer `questionNo`, `questionType: "structured"`, official positive integer `maxMarks`, optional `difficulty`/`topic`, `stem`, `content`, `markScheme`, and optional reviewed chapter mappings. The structured answer is always exposed as `null` and `options` as `[]`; the migration keeps a legacy answer slot for existing MCQ rows, but structured imports must never put an option number there. Never infer an answer or a difficulty label.

The stable ID is `CIE-ASAL-<subjectCode>-<paperSlug>-<two-digit-questionNo>`, generated by `stableStructuredQuestionId`. A parent question is the smallest selectable unit; subparts have IDs inside `content.parts` and are not separate question-bank rows.

Both `content` and `markScheme` support ordered `images` and `blocks`. A fragment is `{url, storageKey, order, page, crop:{x,y,width,height}}`; `page` is the original PDF page number starting at 1, and crop coordinates are PDF points. Fragment URLs use the content API. Preserve original text, pseudocode indentation, tables, and diagrams in images. Readers/exporters prefer ordered images when present and use blocks as the accessible fallback, so do not embed the same image a second time in `blocks`.

Blocks are `{type:"text",text}`, `{type:"code",text,language?}`, `{type:"table",headers:[],rows:[[]]}`, or `{type:"image",url,storageKey?}`. Code text retains literal whitespace. `content.sharedMaterials` is a block array; `content.parts` is an ordered recursive array of `{id,label,maxMarks,prompt:[blocks],children:[],dependsOn:[]}`. Labels retain original numbering, such as `(a)` and `(i)`. Dependency IDs must refer to parts in that same parent question. `markScheme.parts` uses `{partId,blocks:[blocks]}` to pair official criteria with parts. The site does not generate criteria.

Missing QP or MS bytes are reported for the specific parent question and block the corresponding PDF export. Question and MS PDFs use the same selected parent order and retain original subpart labels and source slugs. Image fragments paginate at readable width; long single images are split across pages rather than reduced to fit a page.

## Rollout

Apply migration `0019_9618_structured_content.sql`, deploy the Worker and static assets, and verify the zero-resource 9618 page. Import production resources independently later. Check the prepared manifest, upload declared files, upsert draft rows, verify file pairing and actual metadata, then publish and reload the catalog. The frontend enables available content from the returned resources; no new subject page or hardcoded syllabus edition is needed.
